# Running ia-reviver on a NixOS qBittorrent host

This walks through wiring ia-reviver onto a host managed by
`services.qbittorrent` — the standard setup: qBittorrent
running as a systemd service, a WebUI on localhost, a big `save_path` on disk.

The flake deliberately ships no NixOS module. What follows is configuration you
own, in your own `nixos-config`, so it stays reviewable and version-pinned with
the rest of your system.

## 1. Know what your qBittorrent module actually gives you

From `nixos/modules/services/torrent/qbittorrent.nix`, on a host like:

```nix
# apps/qbittorrent/default.nix
{ user, ... }: {
  services.qbittorrent = {
    enable = true;
    inherit user;          # the service runs as this user
    group = "users";
    openFirewall = true;
  };
}
```

the relevant facts are:

| Setting | Default | Note |
|---|---|---|
| `services.qbittorrent.user` / `.group` | `qbittorrent` / `qbittorrent` | the account the systemd unit runs as |
| `services.qbittorrent.profileDir` | `/var/lib/qBittorrent` | config lives at `<profileDir>/qBittorrent/config/qBittorrent.conf` |
| `services.qbittorrent.webuiPort` | `8080` | passed to `qbittorrent-nox --webui-port` |
| `services.qbittorrent.serverConfig` | `{}` | free-form, written straight into `qBittorrent.conf` |

Two consequences that actually matter here:

- **The config directory is `0700`-ish and owned by `cfg.user`.** ia-reviver
  never touches it — it only speaks the WebUI API — so it does not need access.
- **`PrivateTmp = true` is *not* set, but `ProtectSystem = "full"` is**, so
  anything you bolt on must write only where it legitimately can. ia-reviver
  writes into the torrent's `save_path` and its own `state_dir`; that is it.

## 2. Give ia-reviver a way to log in

If no WebUI password is configured, qBittorrent generates a temporary one at
startup and logs it:

```console
$ journalctl -u qbittorrent | grep -i -A2 "temporary password"
```

For a permanent setup, set the credentials declaratively through
`serverConfig` (note the PBKDF2 format is qBittorrent-specific):

```nix
services.qbittorrent.serverConfig = {
  LegalNotice.Accepted = true;
  Preferences.WebUI = {
    Username = "admin";
    # Generate the format with qBittorrent itself, or with
    # https://codeberg.org/feathecutie/qbittorrent_password
    Password_PBKDF2 = "…generated byte array…";
    # Bind to localhost only: ia-reviver runs on this machine.
    Address = "127.0.0.1";
  };
};
```

Because ia-reviver runs on the same host, keep the WebUI on `127.0.0.1`. There
is never a reason to expose it for this.

## 3. Run it as the same user as qBittorrent

This matters. ia-reviver writes torrent payloads directly into the torrent's
`save_path`. If it runs as a different user than `services.qbittorrent.user`, the
files can end up unreadable to qBittorrent and the recheck will silently never
reach 100%.

So: `User = config.services.qbittorrent.user` in the service below, and make sure
the group matches too (`Group = "users"` in the example host).

## 4. A one-shot service and a nightly timer

Add the flake as an input:

```nix
# flake.nix of your nixos-config
inputs.ia-reviver.url = "github:dbeley/archive-org-torrent-reviver";
```

Then pass the flake down to the host module:

```nix
# hosts/qbittorrent-host/default.nix
{
  config,
  inputs,
  pkgs,
  ...
}:
let
  ia-reviver = inputs.ia-reviver.packages.${pkgs.stdenv.hostPlatform.system}.default;
in
{
  environment.systemPackages = [ ia-reviver ];

  sops.secrets."qbittorrent_password" = {
    owner = config.services.qbittorrent.user;
    # mode = "0400";  # sops-nix defaults to 0400
  };

  systemd.services.ia-reviver = {
    description = "Populate unseeded archive.org torrents from archive.org";
    after = [ "qbittorrent.service" ];
    wants = [ "network-online.target" ];
    serviceConfig = {
      Type = "oneshot";
      User = config.services.qbittorrent.user;
      Group = config.services.qbittorrent.group;

      # The password arrives as a systemd *credential* rather than an argument,
      # so it never appears in `ps` or in the journal.
      LoadCredential = "qb_password:${config.sops.secrets."qbittorrent_password".path}";
      Environment = [
        "IA_REVIVER_QB_URL=http://127.0.0.1:${toString config.services.qbittorrent.webuiPort}"
        "IA_REVIVER_QB_USERNAME=admin"
        "IA_REVIVER_QB_PASSWORD_FILE=%d/qb_password"
        "IA_REVIVER_STATE_DIR=/var/lib/ia-reviver"
      ];

      ExecStart = "${ia-reviver}/bin/ia-reviver revive --all --yes --limit-rate 20M";

      # Hardening, in the spirit of the qBittorrent unit itself.
      NoNewPrivileges = true;
      PrivateDevices = true;
      ProtectHome = "yes";
      ProtectKernelLogs = true;
      ProtectKernelModules = true;
      ProtectKernelTunables = true;
      ProtectClock = true;
      ProtectControlGroups = true;
      ProtectHostname = true;
      RestrictAddressFamilies = [ "AF_INET" "AF_INET6" "AF_UNIX" ];
      RestrictNamespaces = true;
      LockPersonality = true;
      MemoryDenyWriteExecute = true;
      SystemCallFilter = [ "@system-service" ];
    };
  };

  systemd.timers.ia-reviver = {
    wantedBy = [ "timers.target" ];
    timerConfig = {
      OnCalendar = "daily";
      RandomizedDelaySec = "1h";   # be gentle with archive.org
      Persistent = true;           # catch up after downtime
    };
  };
}
```

Two notes on that config:

- `%d` in `IA_REVIVER_QB_PASSWORD_FILE` is the systemd credential directory that
  `LoadCredential` populates. The password is then read from a file owned by
  root and readable only by the unit, and never becomes a command-line argument.
- `--limit-rate 20M` on a long-running box is a deliberate throttle. archive.org
  is donation-funded; the nightly job should not saturate the uplink.

> **The hardening block is a starting point, not a tested configuration.** The
> sandboxing options mirror the ones the qBittorrent unit itself uses, and
> ia-reviver is pure-stdlib Python doing HTTPS, so nothing there should be
> required at runtime — but this exact combination has not been run on a NixOS
> host. If the unit fails with an opaque error, drop the hardening lines first
> and re-add them one at a time. (`systemd-analyze security ia-reviver.service`
> is the quick check.)

`/var/lib/ia-reviver` needs to exist and be writable by that user:

```nix
systemd.tmpfiles.rules = [
  "d /var/lib/ia-reviver 0750 ${config.services.qbittorrent.user} ${config.services.qbittorrent.group} -"
];
```

## 5. Try it by hand first

```console
$ nix run github:dbeley/archive-org-torrent-reviver -- \
    --qb-url http://127.0.0.1:8080 --qb-username admin \
    --qb-password-file /run/secrets/qbittorrent_password \
    check

$ # read-only: what is dead, and how much would be downloaded
$ nix run github:dbeley/archive-org-torrent-reviver -- \
    --qb-url http://127.0.0.1:8080 --qb-username admin \
    --qb-password-file /run/secrets/qbittorrent_password \
    scan

$ # then, deliberately, one torrent
$ nix run github:dbeley/archive-org-torrent-reviver -- \
    --qb-url http://127.0.0.1:8080 --qb-username admin \
    --qb-password-file /run/secrets/qbittorrent_password \
    revive <identifier> --yes --limit-rate 20M
```

Then refresh the WebUI: the torrent should now show as seeding, with a real
`↑` rate where before it sat at `stalledDL` with no peers.

## 6. Keeping state and logs

The tool writes two things worth knowing about under `state_dir`:

- `locks/<hash>.lock` — one per torrent, so two overlapping runs cannot write
  the same files. Stale locks from a dead PID are taken over automatically.
- `history/revived.jsonl` — append-only record of every run: torrent, item,
  bytes fetched, progress before and after, and whether the client's own check
  confirmed completion. This is the honest record; if a run reports success, it
  is because qBittorrent said so, and that is what lands here.

Query it:

```console
$ jq -r 'select(.completed) | "\(.identifier) \(.fetched_bytes)"' \
    /var/lib/ia-reviver/history/revived.jsonl
```

## 7. When it does not work

**The recheck finishes at less than 100%.** The most common cause is a stale
local torrent: archive.org regenerated the item's `.torrent`, so the file list
no longer matches what you have. ia-reviver detects this and refuses unless
`--force` is given. The fix is to remove the torrent *without* deleting data and
add the current `.torrent` from the item page, then re-run.

**`403` from qBittorrent.** Either the password is wrong, or the client banned
the source IP after too many failures — qBittorrent distinguishes these two
(`Fails.` vs `Your IP has been banned`), and so does the tool's error output.

**Permission denied writing into `save_path`.** `User` in the unit does not match
`services.qbittorrent.user`, or the directory is not group-writable. Check
ownership on the torrent's `save_path`; the files must end up readable by the
qBittorrent user for the recheck to succeed.

**A torrent still shows no seeders after a successful recheck.** That is the
tracker's view, not the client's. Re-announce by restarting the torrent, and give
it a few minutes — archive.org's trackers are not instant.
